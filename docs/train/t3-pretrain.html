T3 從零開始預訓練 ​

本章屬性

  • 等級: ◇ 選讀
  • 狀態: 可閱讀 (部分資料待核對)
  • 資料基準日: 2026-10-27
  • 待查證: Llama 3.1 的 token 數與 GPU 時數取自 Hugging Face 上轉載的模型卡 (二手來源), Meta 官方頁面本輪未擷取; OLMo 系列各版本的 token 數本輪未查到官方數字; nanoGPT 的指令未實機驗證; 「多數讀者不需要預訓練」為整理者判斷; 文中的類比為整理者所寫, 不代表技術上完全等同

結論: 從零預訓練一個實用的語言模型, 需要數兆個 token 的資料與數百萬 GPU 小時的運算, 超出個人與一般企業的能力範圍. 以公開數字為例, Llama 3.1 用了約 15 兆個 token 預訓練, 其中 8B 模型就用了 146 萬個 H100 GPU 小時. 讀者若要讓模型學會自己的格式與規則, 應先用檢索 (M4) 或微調 (T2). 預訓練只適合當作學習題材, 用教學用的小型專案了解模型如何訓練.

本章常見名詞

詞意思
預訓練 (pretraining)從隨機的數字開始, 讓模型讀大量文字, 學會語言與知識
token模型處理文字的最小片段, 見 K1
GPU 小時一張 GPU 運算一小時; 1,000 GPU 小時可以是 1 張卡跑 1,000 小時, 也可以是 1,000 張卡跑 1 小時
去重 (deduplication)刪除重複或幾乎重複的文件
語料 (corpus)為訓練蒐集的大量文字

完整詞彙見術語對照.

T3.1 規模概念與算力需求 ​

預訓練和微調的差別, 可以想成從小學開始的完整教育, 對照到職後的專業訓練: 前者要讀完大量的書才能學會語言與常識, 後者只是在已經受過教育的人身上補強特定技能. 下表是公開模型揭露的預訓練規模:

模型預訓練資料量運算量來源
Llama 3.1 (8B, 70B, 405B)約 15 兆個 token, 資料截至 2023 年 12 月三種大小合計 3,930 萬 H100-80GB GPU 小時; 8B 為 146 萬, 70B 為 700 萬, 405B 為 3,084 萬Llama 3.1 模型卡 (Hugging Face 轉載)
Gemma 327B 為 14 兆, 12B 為 12 兆, 4B 為 4 兆, 1B 為 2 兆, 270M 為 6 兆個 token以 TPUv4p, TPUv5p 與 TPUv5e 訓練, 未揭露時數Gemma 3 模型卡
GPT-2 (124M) 的教學重現OpenWebText 語料單一 8 張 A100 40GB 的節點約 4 天nanoGPT README

以 Llama 3.1 8B 為例, 146 萬 GPU 小時若只用 8 張同級 GPU, 約需 182,500 小時, 也就是約 21 年 (計算值: 1,460,000 ÷ 8 ÷ 24 ÷ 365). 相對地, T1.3 引用的 Unsloth 文件標示, 用 QLoRA 微調同一等級的 8B 模型, 最低只需約 6GB 的顯示記憶體. 兩者的差距, 是本章建議多數讀者不要預訓練的主要理由 (推論, 信心: 高).

GPT-2 124M 只有 1.24 億個參數, 約是 8B 模型的六十四分之一, 即使如此, 重現一次仍需 8 張資料中心級 GPU 跑約 4 天 (來源: nanoGPT README). 這類小模型適合學習, 不適合實際工作 (推論, 信心: 中高).

T3.2 資料蒐集, 授權與去重 ​

預訓練的資料決定模型會說什麼語言, 知道什麼事, 以及會不會重現不該出現的內容. 可以想成編一套教科書: 書的來源要合法, 內容要正確, 同一篇文章重複印十次並不會讓學生學得更好.

資料來源與授權: 公開的大型語料多半附有明確授權. 例如 Hugging Face 的 FineWeb2 涵蓋超過 1,000 種語言的網頁文字, 採 ODC-By 1.0 授權 (來源: FineWeb2 GitHub 儲存庫與資料卡); 維基百科的資料庫備份採 GFDL 與 CC BY-SA 4.0 (來源: Wikimedia dumps 授權說明); Ai2 的 Dolma 是含 3 兆個 token 的開放英文語料, Ai2 並公開其 OLMo 系列模型的訓練程式, 訓練資料, 權重與訓練方法 (來源: Ai2 文件 OLMo). 自行爬取網頁時, 每個網站的使用條款不同, 需要逐一確認 (推論, 信心: 高).

過濾: Google 在 Gemma 3 模型卡說明, 預訓練資料在多個階段過濾兒少性剝削內容, 並以自動化方法過濾部分個人資訊與其他敏感資料 (來源: Gemma 3 模型卡). 自行蒐集語料時, 這兩類過濾都應納入流程 (推論, 信心: 高).

去重: 網頁上有大量重複或幾乎相同的內容, 例如轉貼文章與範本頁面. FineWeb2 的資料卡說明, 每種語言的資料都已做過全域去重, 使用者不必再自行去重 (來源: FineWeb2 資料卡); 其儲存庫的中繼資料欄位 minhash_cluster_size 顯示, 去重以 MinHash 分群的方式進行 (來源: FineWeb2 GitHub 儲存庫). MinHash 是一種快速估算兩份文件相似程度的方法, 能在大量文件中找出幾乎重複的內容. 去重可以避免把運算花在重複內容上, 也能降低模型逐字記住特定文字的機會 (推論, 信心: 中).

T3.3 為何多數讀者不需要 ​

讀者想讓模型「懂自己的業務」時, 有三條路可走. 可以想成讓一位新人上手: 給他一份手冊 (檢索), 安排一段在職訓練 (微調), 或是從小學開始重新教育 (預訓練). 下表比較三者 (整理者整理, 推論, 信心: 中):

面向檢索 (M4)微調 (T2)預訓練 (本章)
改變什麼不改模型, 回答時提供相關文件改變模型回答的格式, 語氣與判斷規則從頭建立模型的語言能力與知識
需要的資料自己的文件即可數百至數千筆高品質問答範例 (見 T1.2)數兆個 token 的語料
需要的硬體推論用硬體即可QLoRA 微調 8B 模型最低約 6GB 顯示記憶體數百萬 GPU 小時 (見 T3.1)
資料更新時更新文件即可重做資料與訓練實務上無法頻繁重訓

整體而言, 業務知識放檢索, 回答方式用微調, 預訓練則留給有大型運算資源的研究機構與模型廠商 (推論, 信心: 高).

T3.4 選讀: 用教學專案了解訓練過程 ​

想實際看到「模型如何從零學會寫字」的讀者, 可以用教學用的小型專案練習. 這類專案的角色不是產出可用的模型, 而是把訓練迴圈 (讀資料, 計算誤差, 調整參數, 重複) 寫得夠短, 讓人能逐行讀懂.

nanoGPT 是常被引用的教學專案, 自述為「訓練與微調中型 GPT 最簡單, 最快的儲存庫」, 授權為 MIT. 最快的入門範例是用莎士比亞作品訓練一個以字元為單位的小模型: README 表示, 在一張 A100 上約 3 分鐘可完成; 只用 CPU 時改用更小的模型, 同樣約 3 分鐘, 但驗證損失較高 (1.88, A100 版本為 1.4697); 在 Apple 晶片的 Mac 上加上 --device=mps 可用內建 GPU 加速 (來源: nanoGPT README). 損失是衡量模型猜錯程度的數字, 越低代表猜得越準.

README 同時說明, 這個儲存庫已經很舊並停止維護, 只是保留供參考, 並建議改看作者後來發布的 nanochat (來源: nanoGPT README). 用 nanoGPT 學習訓練迴圈的概念仍然可行, 但套件版本可能與目前的環境不相容 (推論, 信心: 中).
