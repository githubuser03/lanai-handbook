第 1 章 使用說明與自我檢測 ​

本章屬性

  • 等級: ● 必要
  • 狀態: 可閱讀 (部分資料待核對)
  • 資料基準日: 2026-10-26
  • 待查證: 1.3 節的硬體查詢指令未實機驗證; 硬體等級 E, F 的規格門檻待第 7 章定義

結論: 回答三個問題, 就能找到自己的閱讀路徑: 想做什麼, 手上是什麼硬體, 之後誰維運. 多數讀者只需要讀「必要」章節, 加上一至兩個依情境才讀的章節.

本手冊整理如何在自己的機器或機房內執行 AI 模型, 範圍涵蓋概念, 評估選擇, 架設部署, 應用擴充, 訓練微調與維運更新. 手冊不預設地端優於雲端, 也不包含法規解讀; 涉及法規的決定, 請洽法律顧問.

1.1 先回答三個問題 ​

問題選項
1. 想做什麼a. 自己用, 與模型對話 / b. 讓模型回答自己的文件 / c. 給 2 人以上共用 / d. 想訓練或微調 / e. 還在評估該不該自架
2. 手上是什麼硬體見 1.3 節, 對應等級 A 至 F
3. 之後誰維運有人每週檢查安全公告與備份 / 沒有固定的人

第 3 題的答案會限制可選的架構: 沒有人固定維運時, 請只採用最小組合 (第 9.1 節), 並在第 3 章分層圖中只保留 ● 必要層.

1.2 依目的選閱讀路徑 ​

目的建議順序說明
a. 自己用第 3 章 → 第 5, 7 章 → 第 8 章 → 第 9.1 節 → 第 18, 19 章先確認硬體跑得動模型, 再依最小組合架設
b. 問自己的文件上列路徑 → 第 12 章 → 第 14 章檢索增強生成 (RAG) 的品質取決於文件解析與嵌入模型, 需要自建測試題
c. 多人共用第 3 章 → 第 9.2 節 → 第 10, 11 章 → 第 18 至 20 章重點在帳號, 網路隔離與備份; 閘道依第 10.1 節條件才加
d. 訓練或微調第 15 章 (先判斷是否需要) → 第 16 章多數需求用提示與檢索即可, 見第 15 章
e. 評估該不該自架「決策參考」整組頁面見 1.4 節

1.3 硬體自我檢測 ​

查出自己的規格 ​

以下指令未實機驗證, 輸出欄位名稱會因作業系統版本而異; 若與說明不符, 以系統設定畫面為準.

系統指令看什麼
Windows 或 Linux, 有 NVIDIA 顯示卡nvidia-smi --query-gpu=name,memory.total,driver_version --format=csv顯示卡型號, 顯示記憶體, 驅動版本
macOSsystem_profiler SPHardwareDataType晶片 (是否為 Apple Silicon) 與記憶體
Linuxfree -h系統記憶體
Windows (PowerShell)Get-CimInstance Win32_ComputerSystem | Select-Object TotalPhysicalMemory系統記憶體 (單位為位元組)

對應等級 ​

等級特徵建議起點
A無獨立顯示卡的筆電最小組合, 桌面版介面 (第 9.4 節)
B8 至 12GB 顯示記憶體最小組合
CApple Silicon Mac, 以統一記憶體容量決定能力16GB 用最小組合; 32GB 以上可考慮標準組合
D16GB 顯示記憶體標準組合
E預算較高的單機配置標準組合 (規格門檻待第 7 章定義)
F預算更高的多卡或大容量配置進階組合 (須有人每週維運)

顯示記憶體 (或統一記憶體) 比運算速度更常決定「模型跑不跑得起來」, 估算方法見第 5 章. 此對應表來自研究 1 的分級, 待以第一手報價與規格核對 (信心: 中).

1.4 決策者: 先看這幾頁 ​

不需要先懂技術, 也能判斷該不該自架. 建議順序如下:

  1. 一頁決策摘要: 三分鐘看完結論與前提.
  2. 該不該自架決策樹: 依資料敏感度, 使用人數與維運能力判斷.
  3. 成本試算表: 自己填入數字, 比較自架與雲端 API.
  4. 風險自評: 十個問題, 看維運前提是否成立.
  5. 授權紅旗: 對外提供服務前, 哪些授權條款要先處理.
  6. 30 天 PoC 計畫: 用最小代價驗證, 再決定是否投入.

標示意義

◇ 進階或選讀初階讀者可以略過
撰寫中 (僅有大綱)只有章節骨架, 尚無可用內容
可閱讀 (部分資料待核對)內容可參考, 但標示「待核對」的數字或來源尚未以第一手資料確認
已審閱內容與來源經人工逐項核對
未實機驗證指令依官方文件整理, 尚未在實機執行; 執行前請先在測試環境試跑
信心: 高 / 中 / 低超出事實的判斷所附的信心水準; 標「推論」者為整理者推論

正文只寫原則與判斷流程. 版本號, CVE, 價格與基準分數一律放在參考資料, 並標示來源與資料基準日.
