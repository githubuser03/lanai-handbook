使用說明與學習路線 ​

本頁屬性

  • 等級: ● 必要
  • 狀態: 可閱讀 (部分資料待核對)
  • 資料基準日: 2026-10-26
  • 待查證: 硬體自我檢測的查詢指令未實機驗證; 硬體等級 E, F 的規格門檻待 K3 定義; 硬體等級 A 至 F 的分級來自研究 1 (內部研究紀錄, 非公開來源), 無公開佐證, 來源待補

結論: 本手冊以一張架構圖為終點, 分四部帶讀者走到那裡: 第一部講懂每個元件背後的原理, 第二部一次組裝一個模組, 第三部用範例說明組好的系統能解決什麼問題, 第四部是長期維運. 先選一條學習路線, 再依路線閱讀.

本手冊整理如何在自己的機器或機房內執行 AI 模型. 手冊不預設地端優於雲端, 也不包含法規解讀; 涉及法規的決定, 請洽法律顧問.

全書結構 ​

部內容讀完能做到
架構地圖最終要組出的系統, 以及每一塊由哪個模組組裝知道自己需要哪幾塊
第一部 底層知識 (K1 至 K6)模型, 量化, 硬體, 授權, 工具呼叫, 安全看懂圖上每個方塊在做什麼, 為什麼要這樣分區
第二部 模組化組裝 (M0 至 M9)由下往上, 每章組裝一個模組, 附驗收測試一步一步把系統架起來
第三部 應用範例 (P1 至 P3, E1 至 E5)個人與企業的常見用途知道組好的系統怎麼用在日常工作
第四部 維運 (O1 至 O3)備份, 版本鎖定, 安全公告讓系統長期安全運作

另有決策參考 (該不該自架, 成本, 風險) 與延伸主題訓練微調.

先回答三個問題 ​

問題選項
1. 想做什麼a. 自己用 / b. 給 2 人以上共用 / c. 還在評估該不該自架 / d. 想訓練或微調
2. 手上是什麼硬體見下方「硬體自我檢測」, 對應等級 A 至 F
3. 之後誰維運有人每週檢查安全公告與備份 / 沒有固定的人

第 3 題的答案會限制能組到哪裡: 沒有人固定維運時, 只組到里程碑 1 (M0 至 M2).

選一條學習路線 ​

路線閱讀順序終點
a. 個人路線架構地圖 → K1, K2, K3 → M0 (單機做法) → M1 → M2 → 需要問文件時加 M4 → 範例 P1 至 P3 → O1, O2里程碑 1, 視需要加檢索
b. 企業路線架構地圖 → K1 至 K6 → M0 至 M6 (里程碑 2) → 有人每週維運時再加 M7 至 M9 (里程碑 3) → 範例 E1 至 E5 → O1 至 O3里程碑 2 或 3
c. 決策者路線決策參考整組頁面 → 架構地圖判斷要不要投入, 投入到哪個里程碑
d. 訓練或微調T1 (先判斷是否需要) → T2多數需求用提示與檢索即可, 見 T1

每個模組章都依同一個格式撰寫: 這一塊在圖上的位置, 前置模組, 安裝步驟, 驗收測試, 完成後的狀態. 組完一章再進下一章, 遇到問題時比較容易找出是哪一塊出錯.

對應等級 ​

等級特徵建議起點
A無獨立顯示卡的筆電里程碑 1, 桌面版介面 (見組裝總覽的硬體對應)
B8 至 12GB 顯示記憶體里程碑 1
CApple Silicon Mac, 以統一記憶體容量決定能力16GB 組到里程碑 1; 32GB 以上可組到里程碑 2
D16GB 顯示記憶體里程碑 2
E預算較高的單機配置里程碑 2 (規格門檻待 K3 定義)
F預算更高的多卡或大容量配置里程碑 3 (須有人每週維運)

顯示記憶體 (或統一記憶體) 比運算速度更常決定「模型跑不跑得起來」, 估算方法見 K2. 此對應表來自研究 1 的分級 (研究 1 為內部研究紀錄, 非公開來源), 待以第一手報價與規格核對 (信心: 中).

決策者: 先看這幾頁 ​

不需要先懂技術, 也能判斷該不該自架. 建議順序如下:

  1. 一頁決策摘要: 三分鐘看完結論與前提.
  2. 該不該自架決策樹: 依資料敏感度, 使用人數與維運能力判斷.
  3. 成本試算表: 自己填入數字, 比較自架與雲端 API.
  4. 風險自評: 十個問題, 看維運前提是否成立.
  5. 授權紅旗: 對外提供服務前, 哪些授權條款要先處理.
  6. 30 天 PoC 計畫: 用最小代價驗證, 再決定是否投入.

參考來源 ​

本頁的全書結構, 學習路線, 三個問題, 等級對應與完成度表是整理者的設計, 事實依據在各章; 等級 A 至 F 的分級來自研究 1 (內部研究紀錄, 非公開來源, 無公開佐證). 頁內查詢指令的出處如下, 指令均未實機驗證.

  • nvidia-smi --query-gpu=name,memory.total,driver_version --format=csv: NVIDIA 官方文件說明 --query-gpu 接受以逗號分隔的屬性清單, --format=csv 輸出 CSV. 該頁未列出 name, memory.total, driver_version 三個屬性名稱, 並指向 --help-query-gpu 查詢可用屬性, 因此使用前請先在自己的機器上執行 nvidia-smi --help-query-gpu 核對. NVIDIA: nvidia-smi 文件
  • system_profiler SPHardwareDataType: 指令說明取自 Apple man page 的網路鏡像 (二手來源), 其中 -listDataTypes 可列出可用的資料類型; 資料類型名稱 SPHardwareDataType 取自第三方指令參考站 (二手來源), 請以 system_profiler -listDataTypes 的輸出核對. system_profiler(8) man page (鏡像), ss64: system_profiler
  • free -h: man page 說明 -h (--human) 以易讀的單位顯示記憶體量. free(1) man page
  • Get-CimInstance Win32_ComputerSystem 的 TotalPhysicalMemory: Microsoft 文件說明單位為位元組; 同頁提醒在某些情況下 (例如 BIOS 保留一部分記憶體) 此值不準確, 精確值應改用 Win32_PhysicalMemory 的 Capacity. Microsoft: Win32_ComputerSystem class
  • Apple Silicon 採統一記憶體: Apple 2020-11 發表 M1 的新聞稿寫明採 unified memory architecture; 各代晶片的記憶體上限與頻寬不在本頁討論範圍. Apple Newsroom: Apple unleashes M1
  • 「顯示記憶體比運算速度更常決定模型跑不跑得起來」: 依據是 K2 的估算算式與 K3, 屬算術與整理者判斷 (信心: 高).
  • 「沒有人固定維運時只組到里程碑 1」: 整理者建議 (推論, 信心: 中), 理由見組裝總覽與 O3.
