O2 版本鎖定與升級流程 ​

本章屬性

  • 等級: ● 必要
  • 狀態: 可閱讀 (指令未實機驗證)
  • 資料基準日: 2026-10-26
  • 待查證: 容器映像摘要值的查詢指令為 Docker 通用做法, 未實機驗證; 各應用程式是否支援資料庫降版, 須逐一查證

結論: 鎖定版本不等於不升級. 做法是「固定在已知版本, 有公告或需求時, 先備份, 先在測試環境驗證, 再升級, 並保留回退的路」. 這樣能避開 2026 年已出現的浮動標籤事件, 又不會因久未更新而累積漏洞 (信心: 中高, 屬推論).

O2.1 版本記錄與固定方式 ​

為什麼不用浮動標籤 ​

2026-10-21 的 LiteLLM 事件中, latest, main-latest, main-stable 等標籤都曾指向惡意映像 (來源: LiteLLM 官方事故報告, 見 M5.3 節). 浮動標籤隨時可能指向不同內容, 不能當作版本固定.

固定方式 ​

對象固定方式
容器映像使用明確的版本標籤; 較嚴格者連同摘要值 (digest) 一起固定
Ollama (Linux)安裝腳本加上 OLLAMA_VERSION 環境變數, 如 curl -fsSL https://ollama.com/install.sh | OLLAMA_VERSION=<版本> sh (來源: Ollama 文件 Linux); 版本號從 GitHub releases 頁取得
Python 套件在需求檔中寫明確版本, 例如 litellm==<版本>
模型檔記錄來源庫與 revision (見 M1.5 節)

查詢本機映像的摘要值 (Docker 通用指令, 未實機驗證):

bash
docker image ls --digests

版本紀錄表 ​

每個元件一列, 每次變動都更新. 這張表同時是還原與稽核時的依據.

元件版本或摘要值安裝或升級日期來源上一版備註

O2.2 升級流程 ​

建議順序 (信心: 中高, 屬推論):

  1. 決定要不要升: 讀發行說明與安全公告 (O3). 漏洞已有利用紀錄時列為優先; 純功能更新可以排到下個維護時段.
  2. 備份: 依 O1備份資料卷, 並確認備份可用.
  3. 在隔離環境先試: 用另一組容器名稱與連接埠, 載入備份的資料, 先升級試跑.
  4. 跑測試集: 用 M6的回歸測試集比較升級前後的結果與耗時.
  5. 正式升級: 以相同的啟動指令與環境變數重建容器; 密鑰類設定要沿用. 例如 Open WebUI 的 WEBUI_SECRET_KEY 若改變, 重建後所有人須重新登入 (來源: Open WebUI Quick Start). 另外, Open WebUI 標為 ConfigVar 的環境變數只在第一次啟動時生效, 升級時改這類變數不會生效, 要在管理介面調整 (來源: Open WebUI 文件 Environment Variable Configuration).
  6. 更新版本紀錄: 填寫 19.1 的紀錄表.
  7. 觀察: 升級後一週內留意日誌 (M1.7 節) 與使用者回報.

以 Open WebUI 為例 (來源: Open WebUI Quick Start; 該文件的範例使用浮動標籤 :main, 本手冊建議改用固定版本):

bash
docker rm -f open-webui
docker pull ghcr.io/open-webui/open-webui:<新版本標籤>
# 以先前相同的 docker run 指令重新啟動, 並沿用同一個 WEBUI_SECRET_KEY

緊急修補 ​

漏洞已有利用紀錄時, 時間比完整驗證重要. 縮短流程但不跳過備份: 備份 → 升級 → 跑核心測試題 → 視結果擴大. 若暫時無法修補, 先降低暴露面: 關閉對外連線, 停用受影響功能, 或暫停服務.

O2.3 回退 ​

回退要事先準備, 事發後才準備會來不及.

對象回退做法
容器映像保留上一版映像與啟動指令, 以上一版標籤重新啟動
資料卷部分應用程式升級時會轉換資料庫結構, 回退舊版可能無法讀取新結構 (推論, 信心: 中高), 因此升級前的備份是回退的依據
Ollama以 OLLAMA_VERSION 重新安裝指定的舊版 (Linux)
模型升級模型時保留舊模型, 確認新模型的測試結果後再移除

回退流程: 停止服務 → 以上一版重新啟動 → 若新版已轉換資料結構, 舊版無法讀取, 還原升級前的備份 → 跑核心測試題確認 → 記錄原因.

O2.4 何時該縮減元件 ​

  • 無法每週檢查安全公告時, 移除非必要元件.
  • 以「架構地圖」分層圖檢視哪些層可以拿掉, 優先拿掉 ○ 與 ◇ 層中用量最低的.
  • 元件的儲存庫已封存, 或長期沒有更新, 且沒有替代維護者時, 規劃替換 (例: 版本頁記載 LLM Guard 的儲存庫已於 2026-07-09 封存).
