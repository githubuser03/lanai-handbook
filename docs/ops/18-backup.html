第 18 章 備份與還原 ​

本章屬性

  • 等級: ● 必要
  • 狀態: 可閱讀 (指令未實機驗證)
  • 資料基準日: 2026-10-26
  • 待查證: Docker 資料卷備份指令為通用做法, Docker 官方頁面 "Back up, restore, or migrate data volumes" 本輪因頁面過長未能擷取, 執行前請對照該頁

結論: 要備份的是「資料與設定」, 不是模型檔. 對話資料庫, 向量庫, 設定檔與測試集每週備份一次, 並至少一份存放在另一台裝置; 備份沒有還原過, 就不算備份 (信心: 高).

18.1 備份範圍 ​

對象是否備份說明
介面的資料卷 (對話, 使用者, 設定)是以 Open WebUI 為例, 資料存放在掛載到 /app/backend/data 的資料卷 (來源: Open WebUI Quick Start)
向量庫資料是重建需要重新嵌入全部文件, 耗時又耗算力
原始文件是向量庫只是衍生資料, 原始文件才是來源
設定檔 (compose 檔, 閘道設定)是納入版本控制
.env 與金鑰是, 但分開存放與一般備份分開, 限制存取, 不放進同一個備份包
測試集 (第 14 章)是回歸測試的依據
版本紀錄 (第 19 章)是還原時要知道當時的版本
Modelfile 與自訂腳本是體積小, 重建困難
模型檔否可重新下載; 但要記錄來源與 revision (第 8.5 節)

18.2 備份做法 ​

原則 (信心: 高, 屬通用做法): 備份前先停止會寫入資料的服務, 以免資料庫檔案處於不一致狀態; 備份檔存放到另一台裝置或另一個磁碟, 並保留多個日期的版本.

Docker 資料卷的備份範本 (未實機驗證, 執行前請對照 Docker 官方文件; 映像請固定版本標籤):

bash
docker stop open-webui
docker run --rm -v open-webui:/data -v "$PWD":/backup alpine:<固定版本> \
  tar czf /backup/open-webui-$(date +%F).tar.gz -C /data .
docker start open-webui

備份後立即檢查:

  • [ ] 備份檔大小合理 (不是 0 或異常偏小)
  • [ ] 可列出內容: tar tzf <備份檔> | head
  • [ ] 已複製到另一台裝置或另一個磁碟
  • [ ] 記錄備份日期與來源版本

Open WebUI 官方建議更新前先備份資料卷 (來源: Open WebUI Quick Start), 因此升級流程應把備份放在第一步 (第 19 章).

18.3 還原演練 ​

沒有演練過的備份, 無法確定能用. 演練時不要動正式環境:

  1. 用不同的容器名稱, 資料卷名稱與連接埠 (例如 127.0.0.1:3001) 啟動一份新的介面.
  2. 把備份檔解開到新的資料卷.
  3. 登入並確認: 帳號存在, 舊對話可開啟, 檢索資料可查詢.
  4. 記錄耗時與遇到的問題, 更新還原步驟.
  5. 刪除演練用的容器與資料卷.

建議每季演練一次, 且在大版本升級前加做一次 (頻率為建議值, 屬推論, 信心: 低).

還原到正式環境時, 先保留現有資料卷, 不直接覆蓋, 確認新環境正常後再清理舊資料.

18.4 定期檢查表 ​

頻率工作
每週執行備份並檢查; 檢查安全公告 (第 20 章)
每月比對 CISA KEV 清單; 評估是否有版本需升級; 檢視備份保留份數與磁碟空間
每季還原演練; 檢視帳號清單; 檢視金鑰存放位置
升級前先做一次備份, 並確認該備份可還原

18.5 備份本身的安全 ​

備份檔含有對話內容與使用者資料, 與正式環境同樣敏感 (信心: 高). 存放備份的裝置要有存取控制; 若備份離開機房或放到雲端, 先加密, 並決定金鑰由誰保管.
