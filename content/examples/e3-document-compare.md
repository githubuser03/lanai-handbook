# E3 合約與法規文件比對

::: info 本章屬性
- 等級: ○ 依情境
- 狀態: 可閱讀 (部分資料待核對)
- 資料基準日: 2026-10-26
- 待查證: 比對腳本與設定依 Python 與 Open WebUI 官方文件整理, 未實機驗證; 法規條文的官方開放資料格式與下載方式未查證; 模型對長篇合約與法規條文的比對準確度無公開基準; 文中的類比為整理者所寫, 不代表技術上完全等同
:::

**結論**: 合約版本比對與法規對照需要里程碑 2 (M0 至 M6). 做法分兩步: 差異由程式找出 (例如 Python 的 difflib), 模型只負責說明每一處差異的意義與分類; 法規對照則把官方公布的條文放進獨立的知識庫, 模型逐條列出內部文件與條文的對應及缺口, 每一項都附條號. 本範例的輸出不是法律意見, 須由法務或法遵專業人員確認後才能使用.

**對象**: 企業. **需要的模組**: M0 至 M6.

## 情境

法務與法遵人員常做兩種比對工作:

1. **合約版本比對**: 對方送回修改過的合約, 但沒有開啟追蹤修訂, 或只寄來 PDF. 承辦人要逐條找出哪裡改了, 再判斷改動是否影響公司權利義務.
2. **內部文件對照法規**: 法規修正後, 要找出內部辦法有哪些條文須跟著調整, 或檢查一份內部政策是否涵蓋法規要求的事項.

兩種工作都很耗時, 而且合約與內部文件屬機密, 不一定適合交給雲端服務. 本範例的設計前提是: 模型擅長說明與歸類, 但在長篇文件中「找出所有差異」不可靠, 容易漏掉一個數字或一個「不」字 (推論, 信心: 中高). 所以找差異交給程式, 判斷交給專業人員, 模型居中整理. 可以想成把新舊兩頁疊在燈箱上, 先由燈箱照出所有不同處, 再請助理在每一處旁邊寫上註記, 最後由律師逐處判斷; 助理只負責寫註記, 不負責找出不同處.

## 流程

A 流程處理合約: 兩版文件先轉成文字並統一格式, 由程式逐條找出差異, 模型只為每一處差異寫說明, 最後由法務人員確認. B 流程處理法規: 官方條文放進只有法遵人員能讀的知識庫, 每次拿一條內部規定去找對應法條, 模型列出對照結果, 程式再檢查模型寫出的條號是否真的存在.

```
A. 合約版本比對

[法務人員] --上傳新舊兩版 (Word 或 PDF)--> [入口區: 比對批次作業]
      |
      | 1. docling-serve 把兩版轉成文字, 依條次切開
      | 2. 統一格式 (全半形, 空白與換行)
      | 3. difflib 逐條比對, 輸出差異清單 (條次, 舊文字, 新文字)
      v
[差異清單] --上傳--> [Open WebUI: 「合約差異說明」專用模型]
      |
      | 4. 每處差異送對話模型 (經 LiteLLM 到 vLLM)
      v
[差異說明表: 條次, 差異類型, 對公司的可能影響, 待確認問題]
      |
      v
[法務人員逐條確認] --> 回覆對方或內部簽核

B. 內部文件對照法規

[法遵人員] --從主管機關公布的正式版本取得條文--> 記錄修正日期
      |
      v
[Open WebUI 知識庫: 法規條文 (只有法遵群組可讀)]
      |
      | 法遵人員逐條貼上內部辦法, 使用「法規對照」專用模型
      v
[檢索相關法條 (Qdrant), 經 LiteLLM 送對話模型]
      | 5. 列出對應條號與差異
      v
[對照表: 內部條文, 對應法條 (條號, 修正日期), 符合 / 部分符合 / 未涵蓋, 說明]
      |
      | 6. 程式檢查: 對照表中的條號是否真的存在於知識庫的條文
      v
[法遵人員確認] --> 修訂內部辦法
```

## 設定要點

以下依 Python 與 Open WebUI 官方文件整理, 未實機驗證.

### 差異由程式產生

Python 標準函式庫的 difflib 提供序列比對: `difflib.unified_diff` 輸出統一差異格式, `difflib.HtmlDiff` 產生左右並排, 標出行內差異的 HTML 表格 (Python 官方文件). 下列簡化範例把新舊兩版依條次逐條比對, 只列出有改動的條次:

```python
import difflib

def compare_clauses(old: dict[str, str], new: dict[str, str]):
    """old, new 為 {條次: 條文} 的對照表, 由 Docling 解析結果依條次切開而得."""
    changes = []
    for no in sorted(set(old) | set(new)):
        a, b = old.get(no, ""), new.get(no, "")
        if a != b:
            diff = "\n".join(difflib.unified_diff(
                a.splitlines(), b.splitlines(), lineterm="",
                fromfile=f"舊版 {no}", tofile=f"新版 {no}"))
            changes.append({"clause": no, "old": a, "new": b, "diff": diff})
    return changes
```

依條次切開的規則 (例如以「第 X 條」為界) 須依自己的合約格式調整. 範例以字串排序條次, 「第10條」會排在「第2條」之前; 條數超過 9 條時, 可改用條次中的數字排序, 差異清單本身不受影響 (整理者以 Python 3.13 執行範例確認). 比對前先統一全半形, 空白與換行, 否則排版差異會淹沒實質差異 (推論, 信心: 高).

### 合約差異說明的提示範本

這份範本交給模型的只有程式產生的差異清單, 並限定差異類型與輸出欄位, 讓模型只說明, 不另外找差異.

```
以下是一份合約新舊版本的差異清單, 每一筆含條次, 舊文字與新文字.
請逐筆整理成表格, 欄位為: 條次, 差異類型, 說明, 對我方的可能影響, 建議確認的問題.
差異類型只能是下列之一: 文字修正, 金額或數量變動, 期限變動, 權利義務變動, 責任或賠償變動, 條款新增, 條款刪除.
規則:
1. 只說明清單中的差異, 不要自行找其他差異.
2. 不確定影響時寫「需法務判斷」.
3. 不提供法律意見, 不判斷條款是否有效.
```

### 法規對照

- **條文來源**: 法規條文應取自主管機關公布的正式版本, 例如法務部的全國法規資料庫 (建議搜尋關鍵字: 全國法規資料庫 法規名稱), 並在檔名記錄法規名稱與修正日期. 不使用來源不明的整理版.
- **獨立知識庫**: 法規條文與內部文件分開成兩個知識庫, 法規知識庫只授權法遵群組讀取 (權限設計見 E1). 每次法規修正, 刪除舊版並匯入新版.
- **對照提示範本**: 範本要求每個條號都出自檢索到的條文, 範本最後的 CONTEXT 佔位符會換成檢索到的法條.

```
以下是一條內部規定, 以及檢索到的法規條文.
請整理成表格: 內部規定 (原文摘錄), 對應法條 (法規名稱, 條號, 修正日期), 對照結果, 說明.
對照結果只能是: 符合, 部分符合, 未涵蓋, 無對應法條.
規則:
1. 每個對應法條都必須出現在參考資料中, 條號照抄, 不得自行推測.
2. 參考資料沒有相關條文時, 填「無對應法條」.
3. 本表僅供專業人員檢視, 不是法律意見.

參考資料:
{{CONTEXT}}
```

- **條號存在檢查**: 模型輸出的條號由程式比對法規知識庫的原文, 找不到的條號標為「待查」. 這一步可以擋下編造的條號, 但無法確認對應是否正確 (推論, 信心: 高).

### 上下文與分段

長篇合約不要一次整份送進模型. 合約比對只送差異清單; 法規對照一次只處理一條內部規定. Open WebUI 的檢索設定 (Top K, 切塊大小) 見 P1 的設定要點; 法規條文建議以一條為一段, 讓檢索結果與條號一一對應 (推論, 信心: 中).

## 驗收方式

**1. 合約比對測試組.** 取一份已結案的合約, 由法務人員手動製作修改版, 刻意放入 20 處已知的實質差異, 涵蓋: 金額, 期限, 責任上限, 管轄法院, 「得」改為「應」, 刪除一個「不」字, 新增條款, 刪除條款; 另加 3 處只改標點或空白的排版差異. 通過標準:

- 程式找出全部 20 處實質差異, 3 處排版差異在統一格式後不列入 (程式比對的結果固定, 解析正確時應為全數).
- 模型的差異類型分類, 由法務人員逐筆評分, 記錄正確率.
- 模型沒有新增清單以外的差異.

**2. 法規對照測試組.** 法遵人員先挑 20 條內部規定, 自行完成對照作為標準答案, 其中至少 3 條在法規中沒有對應. 通過標準: 對應條號全部存在於法規知識庫; 「無對應法條」的題目沒有編出條號; 對照結果與標準答案的一致率由法遵人員決定是否可接受.

**3. 權限測試.** 非法務, 法遵群組的帳號看不到合約差異與法規對照的專用模型與知識庫 (測試方式見 E1).

**4. 回歸測試.** 上述兩組測試併入 M6.1 節的測試集, 換模型或升級後重跑.

## 風險與限制

| 風險 | 影響 | 因應方式 |
|---|---|---|
| 不是法律意見 | 讀者把模型的影響說明當成法律判斷 | 輸出一律標示「不是法律意見, 須由專業人員確認」; 簽核流程保留法務人員的確認欄位 |
| 合約屬高度機密 | 合約內容進入向量庫, 對話紀錄與 Langfuse | 只授權法務群組; 紀錄平台限稽核人員存取並設保存期限; 比對完成後刪除暫存檔 |
| 解析錯誤 | 掃描 PDF 或表格解析錯誤, 導致差異清單有誤 | 比對前預覽解析結果; 掃描檔以原始電子檔為優先 |
| 模型分類或說明錯誤 | 低估一處責任條款的影響 | 差異清單由程式產生, 解析正確時不會漏列; 每一處差異都由法務人員看過 |
| 引用過時或編造的法條 | 依錯誤條文修訂內部辦法 | 只用官方正式版本並記錄修正日期; 程式檢查條號存在; 法遵人員確認 |
| 法規解釋與實務見解 | 條文之外的函釋, 判決與主管機關見解不在知識庫中 | 本範例只做條文層級的對照, 解釋問題交給專業人員 |

需要人工確認的步驟: 每一處合約差異的影響判斷, 每一條法規對照結果, 以及所有對外回覆.
