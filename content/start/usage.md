::: info 本頁屬性

**結論**: 這本手冊整理如何在自己的電腦或機房裡架設 AI. 整份手冊以一張[架構圖](/start/map)為終點, 分四部逐步走到那裡: 第一部講懂每個元件背後的原理, 第二部一次組裝一個模組, 第三部用範例說明組好的系統能解決什麼問題, 第四部是長期維運. 先回答三個問題, 選一條學習路線, 再依路線閱讀即可, 不必從頭讀到尾.

手冊不預設地端優於雲端, 也不包含法規解讀; 涉及法規的決定, 請洽法律顧問.

## 地端是什麼

日常使用的 ChatGPT 之類的 AI 服務, 是跑在別人的資料中心裡 (雲端), 輸入的內容會送到對方的機器上. 「地端」指的是反過來: 把 AI 放在自己擁有的電腦或機房裡運轉, 輸入的資料只在自己的網路內流動.

自己架設, 好處是資料可以留在內部, 代價是硬體, 電費與維護都要自己負責. 多數人需要的不是「裝完就好」, 而是看得懂每一塊在做什麼, 才有辦法判斷哪裡出了問題, 以及哪些風險要先處理. 所以手冊除了步驟之外, 也說明各元件背後的原理與取捨.

## 先回答三個問題

這三個問題決定該從哪裡開始, 以及系統做到多大才合適. 做太大, 會變成沒有人顧得了的負擔; 做太小, 又不夠用.

| 問題 | 選項 |
|---|---|
| 1. 想做什麼 | a. 自己用 / b. 給 2 人以上共用 / c. 還在評估該不該自架 / d. 想訓練或微調 (在現成模型上再教它一些東西) |
| 2. 手上是什麼硬體 | 見下方「硬體自我檢測」, 對應等級 A 至 F |
| 3. 之後誰維運 | 有人每週檢查安全公告與備份 / 沒有固定的人 |

「維運」指系統上線之後的持續照顧: 定期備份資料, 更新軟體, 留意有沒有新發現的安全漏洞. 第 3 題的答案會限制能組到哪裡: 沒有人固定維運時, 只組到里程碑 1 (M0 至 M2). 里程碑是手冊切出的三個階段, 每個階段完成後都是一套可以獨立使用的系統, 不必一次做完. 這個限制的理由是: 越複雜的系統越需要有人定期照顧 (整理者建議, 推論, 信心: 中; 理由見[組裝總覽](/build/overview)與 [O3](/ops/advisories)).

## 硬體自我檢測

AI 模型要先整個放進記憶體才能運轉, 所以決定電腦「跑不跑得動」的, 主要是記憶體容量, 不是 CPU 有多快. 有獨立顯示卡的電腦, 模型通常放在顯示卡自己的記憶體 (稱為顯示記憶體), 容量通常比一般記憶體小得多. Apple Silicon 的 Mac 則不同, 處理器與顯示晶片共用同一塊記憶體 (稱為統一記憶體), 所以整台 Mac 的記憶體容量就是上限. 因此只需要查出三個資訊: 顯示卡型號與顯示記憶體容量, 系統記憶體容量, 以及 Mac 的晶片是不是 Apple Silicon.

### 查出自己的規格

指令是在「終端機」這類可以輸入文字指令的視窗裡執行. Windows 與 Mac 都內建這類視窗, 名稱和開啟方式依系統版本而異, 請以系統說明為準. 輸出會附單位, 讀數字時請留意單位, 只要找出上面三個資訊即可.

以下指令未實機驗證, 輸出欄位名稱會因作業系統版本而異; 若與說明不符, 以系統設定畫面為準.

| 系統 | 指令 | 看什麼 |
|---|---|---|
| Windows 或 Linux, 有 NVIDIA 顯示卡 | `nvidia-smi --query-gpu=name,memory.total,driver_version --format=csv` | 顯示卡型號, 顯示記憶體, 驅動版本 (驅動程式的版本號) |
| macOS | `system_profiler SPHardwareDataType` | 晶片 (是否為 Apple Silicon) 與記憶體 |
| Linux | `free -h` | 系統記憶體 |
| Windows (PowerShell) | `Get-CimInstance Win32_ComputerSystem \| Select-Object TotalPhysicalMemory` | 系統記憶體 (單位為位元組) |

### 對應等級

查出規格後, 對照下表找到自己的等級. 等級只是粗略的起點建議, 不是上限.

| 等級 | 特徵 | 建議起點 |
|---|---|---|
| A | 無獨立顯示卡的筆電 | 里程碑 1, 桌面版介面 (見組裝總覽的硬體對應) |
| B | 8 至 12GB 顯示記憶體 | 8GB 組到里程碑 1; 12GB 以上可組到里程碑 2 |
| C | Apple Silicon Mac, 以統一記憶體容量決定能力 | 16GB 組到里程碑 1; 32GB 以上可組到里程碑 2 |
| D | 16GB 顯示記憶體 | 里程碑 2 |
| E | 24GB 以上, 未滿 48GB 顯示記憶體 | 里程碑 2 |
| F | 48GB 以上顯示記憶體, 或多卡 | 里程碑 3 (須有人每週維運) |

顯示記憶體 (或統一記憶體) 比運算速度更常決定「模型跑不跑得起來」, 估算方法見 K2. A 至 F 是整理者依記憶體容量設計的分級, 不是業界標準; 各等級的定義與可跑的模型大小見 [K3](/know/k3-hardware) 的 K3.1 節 (推論, 信心: 中). 想先知道買什麼設備, 預算多少, 見 [K3 硬體](/know/k3-hardware)與[硬體價格頁](/ref/hardware-prices).

## 標示的讀法

每章開頭的屬性框與正文中的標記, 用來快速判斷這一段可以信到什麼程度.

| 標示 | 意義 |
|---|---|
| ● 必要 | 所有讀者都需要 |
| ○ 依情境 | 符合條件才讀, 條件寫在章首 |
| ◇ 進階或選讀 | 初階讀者可以略過 |
| 撰寫中 (僅有大綱) | 只有章節骨架, 尚無可用內容 |
| 可閱讀 (部分資料待核對) | 內容可參考, 但標示「待核對」的數字或來源尚未以第一手資料確認 |
| 已審閱 | 內容與來源經人工逐項核對 |
| 未實機驗證 | 指令依官方文件整理, 尚未在實機執行; 執行前請先在測試環境試跑 |
| 信心: 高 / 中 / 低 | 超出事實的判斷所附的信心水準; 標「推論」者為整理者推論 |

正文只寫原則與判斷流程. 版本號, CVE (已公開的資安漏洞編號), 價格與基準分數一律放在[參考資料](/ref/versions), 並標示來源與資料基準日.

## 參考來源

本頁的手冊結構, 學習路線, 三個問題, 等級對應與完成度表是整理者的設計, 事實依據在各章; 等級 A 至 F 為整理者依記憶體容量設計的分級, 定義與依據見 K3. 頁內查詢指令的出處如下, 指令均未實機驗證.

- **`nvidia-smi --query-gpu=name,memory.total,driver_version --format=csv`**: NVIDIA 官方文件說明 `--query-gpu` 接受以逗號分隔的屬性清單, `--format=csv` 輸出 CSV. 該頁未列出 `name`, `memory.total`, `driver_version` 三個屬性名稱, 並指向 `--help-query-gpu` 查詢可用屬性, 因此使用前請先在自己的機器上執行 `nvidia-smi --help-query-gpu` 核對. [NVIDIA: nvidia-smi 文件](https://docs.nvidia.com/deploy/nvidia-smi/index.html)
- **`system_profiler SPHardwareDataType`**: 指令說明取自 Apple man page 的網路鏡像 (二手來源), 其中 `-listDataTypes` 可列出可用的資料類型; 資料類型名稱 `SPHardwareDataType` 取自第三方指令參考站 (二手來源), 請以 `system_profiler -listDataTypes` 的輸出核對. [system_profiler(8) man page (鏡像)](https://keith.github.io/xcode-man-pages/system_profiler.8.html), [ss64: system_profiler](https://ss64.com/mac/system_profiler.html)
- **`free -h`**: man page 說明 `-h` (`--human`) 以易讀的單位顯示記憶體量. [free(1) man page](https://man7.org/linux/man-pages/man1/free.1.html)
- **`Get-CimInstance Win32_ComputerSystem` 的 `TotalPhysicalMemory`**: Microsoft 文件說明單位為位元組; 同頁提醒在某些情況下 (例如 BIOS 保留一部分記憶體) 此值不準確, 精確值應改用 `Win32_PhysicalMemory` 的 `Capacity`. [Microsoft: Win32_ComputerSystem class](https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/win32-computersystem)
- **Apple Silicon 採統一記憶體**: Apple 2020-11 發表 M1 的新聞稿寫明採 unified memory architecture; 各代晶片的記憶體上限與頻寬不在本頁討論範圍. [Apple Newsroom: Apple unleashes M1](https://www.apple.com/newsroom/2020/11/apple-unleashes-m1/)
- **「顯示記憶體比運算速度更常決定模型跑不跑得起來」**: 依據是 [K2](/know/k2-quantization) 的估算算式與 [K3](/know/k3-hardware), 屬算術與整理者判斷 (信心: 高).
- **「沒有人固定維運時只組到里程碑 1」**: 整理者建議 (推論, 信心: 中), 理由見[組裝總覽](/build/overview)與 [O3](/ops/advisories).
- **文中的類比與說明**: 整理者所寫, 無外部來源, 不應當作技術定義引用. 其中「模型要先整個放進記憶體才能運轉」依據 K2 的估算算式; 「Windows 與 Mac 都內建終端機類視窗」為一般常識, 開啟方式未查證.
