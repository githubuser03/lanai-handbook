# K5 工具呼叫, MCP 與代理

::: info 本章屬性
- 等級: ○ 依情境
- 狀態: 可閱讀 (K5.1 至 K5.3 僅有大綱)
- 待查證: BFCL 分數取自彙整站 benchmarklist.com, 應改連官方排行榜
- 資料基準日: 2026-10-26
:::

**結論**: 模型本身不會「動手」, 它只會輸出「要呼叫哪個工具, 帶什麼參數」, 由程式去執行. 多數情境不需要代理框架, 以「固定步驟的工作流程程式碼 + 每步一次函式呼叫 + 程式端驗證」取得的可靠度最高 (信心: 中高). MCP 是讓多個客戶端共用同一組工具的標準協定, 代理則是讓模型自己決定下一步; 兩者都屬於符合特定條件才用的元件.

## K5.4 先寫工作流程, 再考慮代理

小模型「選對函式, 填對參數」的單步準確率約 78% 至 88%, 但多輪任務只有約 30% 至 42%.

| 模型 | 總分 | 非即時 AST | 即時 (Live) | 多輪 (Multi-turn) |
|---|---|---|---|---|
| Qwen3-8B (FC) | 42.57% | 87.58% | 80.53% | 41.75% |
| Qwen3-14B (FC) | 41.03% | 84.94% | 80.01% | 34.75% |
| Qwen3-30B-A3B-Instruct-2507 (FC) | 41.39% | 85.77% | 77.94% | 30% |
| Qwen3.5-4B (模型卡自報) | 50.3% | - | - | - |

資料來源: BFCL V4 (Berkeley Function Calling Leaderboard), 經 benchmarklist.com 彙整, 資料匯入日 2026-05-28; Qwen3.5-4B 為模型卡自報.

讓 8B 模型自主串接 5 步以上的工具, 失敗是常態 (信心: 中高). 另有一篇論文 (arXiv 2608.22472) 顯示, 改用「指令遵循式」函式呼叫格式, 可讓 Qwen3-4B 與 8B 在 BFCL 子集提升到 90% 以上, 表示提示格式與流程設計的影響可能大於換框架 (信心: 中).

## K5.5 函式呼叫與 MCP 的取捨

MCP (Model Context Protocol) 最新規格是 2026-07-28 版, 核心改為無狀態, 取消 initialize 交握與 Mcp-Session-Id 標頭, 並新增正式的棄用政策 (12 個月棄用期). 美國 NSA 於 2026-06-02 發布 MCP 安全設計指引.

| 情境 | 建議 |
|---|---|
| 自己撰寫的單一應用, 工具不超過 3 至 5 個, 只有一個客戶端 | 直接用函式呼叫 |
| 同一組工具要給多個客戶端共用 (Open WebUI, IDE, 桌面助理) | 使用 MCP |
| 要使用信譽良好的現成伺服器 | 使用 MCP, 並依 M7.1 節審核 |
| 低階硬體的初階讀者 | 不建議列為入門步驟 |

不建議初階讀者的理由有三: 小模型多輪工具呼叫可靠度低; 每個 MCP 伺服器都是以使用者權限執行的程式; 一般函式呼叫就能完成同樣的事 (信心: 中高). 手冊範例須標註所依據的 MCP 規格版本.
