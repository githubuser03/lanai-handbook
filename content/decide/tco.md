# 成本試算表

::: info 本頁屬性
- 等級: 決策參考
- 狀態: 可閱讀
- 資料基準日: 2026-10-27

**結論**: 自架與雲端的成本差異主要取決於三個數字: 每月實際用量, 硬體可用年數, 維運人時. 其中維運人時多半估得偏低 (信心: 中, 屬推論). 本頁提供公式與填寫表, 不提供市場價格.

::: tip 本頁是試算框架
本頁只提供計算方式, 不提供硬體, 電價與雲端 API 單價; 數字請填入查價當日的官方報價, 並註記查價日期.
:::

## 自架年成本

自架的花費多半在購置時與每週固定發生, 不太隨使用次數增減. 硬體購置價要分攤到預計使用的年數, 稱為攤提; 其他項目則以一年為單位估算.

| 成本類別 | 公式 | 填入數字 |
|---|---|---|
| 硬體攤提 | 購置價 ÷ 預計使用年數 | |
| 電費 | 平均功耗 (kW) x 每日運轉小時 x 365 x 電價 (元/度) | |
| 維運人時 | 每週小時 x 52 x 時薪 | |
| 備份與網路 | 外接硬碟, 雲端備份, 網路費用的年合計 | |
| 汰換準備 | 零件故障或提早汰換的預留金 | |
| **合計 (年)** | 上列加總 | |

## 雲端 API 年成本

雲端 API 依用量收費, 計價單位是 token, 也就是模型處理文字時切出的小片段 (見 [K1](/know/k1-basics)). 輸入與輸出分開計價, 下表的單價以每 100 萬 token 計.

| 成本類別 | 公式 | 填入數字 |
|---|---|---|
| 輸入 token 費用 | 每月輸入 token 數 ÷ 100 萬 x 輸入單價 x 12 | |
| 輸出 token 費用 | 每月輸出 token 數 ÷ 100 萬 x 輸出單價 x 12 | |
| 其他 | 向量嵌入, 檔案儲存等附加費用 | |
| **合計 (年)** | 上列加總 | |

單價請從供應商官方定價頁取得並註記查價日. 每月 token 數可由現有使用紀錄推估; 沒有紀錄時, 先做 [PoC](/decide/poc-30days) 累積一個月的實際用量.

## 損益平衡

損益平衡是兩種做法年成本相同的那一點. 可以想成買車與叫車的比較: 每月里程越高, 買車越划算; 里程很低時, 車價與保養費攤下來反而比較貴.

自架合計 (年) ÷ 雲端合計 (年) 小於 1, 表示以目前用量, 自架的年成本較低. 此比值對用量很敏感: 用量減半, 雲端成本約減半, 而自架的硬體與人時大多不變.

## 示意計算 (數字純屬假設, 非市場資料)

假設購置價 100,000 元, 使用 3 年, 攤提約 33,333 元/年. 假設維運每週 2 小時, 時薪 500 元, 年維運人時 52,000 元. 此時即使不計電費, 自架年成本已約 85,333 元 (33,333 + 52,000). 雲端 API 的年費用低於這個金額時, 雲端較便宜.

此範例只示範算式. 實際的硬體價格, 時薪與用量因情況而異, 結論可能相反.

## 常見遺漏

- 維運人時與假日, 休假時的代理人.
- 硬體閒置期間仍在攤提.
- 模型升級後可能需要更多記憶體, 使硬體提早不夠用.
- 雲端方案的企業折扣, 用量承諾與資料處理條款, 會改變雲端那一欄.

## 參考來源

本頁為整理者設計的成本試算框架. 公式 (硬體攤提, 電費, 維運人時, token 費用) 是一般的成本算式, 表格中的空欄由讀者填寫, 頁內沒有市場價格或統計資料.

- **雲端 API 依每百萬 token 計價, 輸入與輸出分開**: 以 Anthropic (提供 Claude 模型雲端 API 的廠商) 的定價頁為例, 價格以「美元 / MTok」標示, 輸入與輸出各有單價; 其他供應商以其官方定價頁為準, 填寫時須註記查價日. [Anthropic: Pricing](https://platform.claude.com/docs/en/about-claude/pricing)
- **示意計算**: 購置價 100,000 元, 使用 3 年, 每週維運 2 小時, 時薪 500 元, 皆為假設值. 算式為 100,000 ÷ 3 約 33,333 元, 2 x 52 x 500 = 52,000 元, 合計約 85,333 元; 這是算術結果, 不是市場資料.
- **「維運人時多半估得偏低」**: 整理者推論 (信心: 中), 無統計來源. 驗證方式是 [30 天 PoC](/decide/poc-30days) 第 4 週記錄的實際工時.
- **「用量減半, 雲端成本約減半」**: 按量計價下的算術推論; 企業折扣或用量承諾會改變結果, 頁尾已列為常見遺漏.
- **「常見遺漏」清單**: 整理者列出的檢核事項 (推論), 不是引用自調查.
- 文中的類比 (買車與叫車): 整理者所寫, 無外部來源, 不應當作技術定義引用.
