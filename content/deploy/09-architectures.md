# 第 9 章 三種參考架構

::: info 本章屬性
- 等級: ● 必要
- 狀態: 草稿, 待人工審閱
- 資料基準日: 2026-10-26
- 待查證: 記憶體與磁碟占用為研究 2 的推論值, 實機驗證前請視為估計
:::

**結論**: 依人數與需求分三種組合, 由小到大逐步加層. 單人單機用最小組合; 2 至 10 人且需要檢索, 用標準組合; 多人, 多模型且有人每週維運, 才採進階組合.

| 組合 | 適用 | 建議硬體等級 | 額外占用 (推論) |
|---|---|---|---|
| 最小安全組合 | 單人, 單機 | A 至 F | 介面約 0.5 至 1.5GB 記憶體; 磁碟約 2 至 5GB (不含模型) |
| 標準組合 | 家庭或小團隊 2 至 10 人, 含檢索與基本評估 | B, D, E; C 級須為中高記憶體款 | 嵌入模型約 0.6 至 1.2GB; 向量庫約 1 至 2GB; 磁碟約 10 至 30GB |
| 進階組合 | 多人, 多模型, 含閘道, 代理與沙箱 | E 至 F | 閘道加 PostgreSQL 約 1 至 2GB; 磁碟約 50 至 100GB |

資料來源: 研究 2 (2026-10-26), 占用值由各元件公開資料加總推算, 信心: 中.

## 9.1 最小安全組合 (單人, 單機)

**元件**: 推論引擎 (llama.cpp 或 Ollama), 加上一個介面. 等級 A 與 C 建議用 AnythingLLM 桌面版, 其他等級用 Open WebUI 單一容器. 不加閘道, 代理框架與 MCP.

**啟動順序**: 推論引擎 → 介面.

```
[瀏覽器 / 桌面 App]
      | http://127.0.0.1:3000
      v
[Open WebUI 或 AnythingLLM] --127.0.0.1:11434--> [Ollama / llama-server]
      |
   (本機資料卷: 對話, 設定) --> 每週備份
   對外: 無開放連接埠
```

**安全基線檢核表**

- [ ] 所有服務只綁 127.0.0.1
- [ ] 映像或安裝版本已記錄並鎖定
- [ ] 介面已設管理者密碼, 並關閉公開註冊
- [ ] 每週備份資料卷
- [ ] 每月檢查一次更新與安全公告
- [ ] 不在介面中存放雲端 API 金鑰, 或只放低額度金鑰

## 9.2 標準組合 (家庭或小團隊)

**元件**:

- 推論引擎, 搭配 llama-swap (需要多模型輪替時)
- 介面: Open WebUI 或 LibreChat
- 嵌入模型: Qwen3-Embedding-0.6B 或 bge-m3
- 向量庫: 介面內建的, 或 Qdrant
- 文件解析: Docling
- 評估: promptfoo 測試集 (第 14 章)
- 網路: Tailscale

**啟動順序**: 推論引擎 / llama-swap → 向量庫 → 介面 → (排程) 文件解析與匯入 → promptfoo 驗證.

```
[家人 / 同事裝置] --Tailscale (WireGuard)--> [主機 100.x.y.z]
                                              |
                     +------------------------+-----------------+
                     v                        v                 v
               [Open WebUI / LibreChat]  [Qdrant :6333]    [Docling 批次]
                     |  (內部 Docker 網路, 不對外)
                     v
               [llama-swap :8080] --> [llama-server: 對話模型 / 嵌入模型]
   公網: 無連接埠轉發
```

**在最小組合的檢核表之上, 另加**:

- [ ] 以 Tailscale ACL 限定可連入的裝置
- [ ] 每位使用者使用個別帳號
- [ ] RAG 文件來源只限可信資料夾 (對應 OWASP LLM08 與 ASI06, 見第 11.4 節)
- [ ] 升級前先跑 promptfoo 測試集
- [ ] `.env` 權限設為 600

## 9.3 進階組合 (多人, 多模型) ◇

**使用條件**: 有人能每週維運, 且符合第 10.1 節列出的閘道條件. 若不符, 請回到 9.2.

**元件**: 標準組合全部, 加上:

- 閘道: LiteLLM 或 Bifrost 擇一, 以映像摘要值 (digest) 鎖定版本
- Caddy (HTTPS)
- 代理: LangGraph 程式庫, 嵌入自己撰寫的服務
- 沙箱化的程式碼執行容器
- 少量已審核, 已容器化的 MCP 伺服器
- 可選: Langfuse (另備至少 12GB 記憶體給 ClickHouse 與 Redis 等), Prompt Guard 2 22M

**啟動順序**: PostgreSQL / Redis → 推論 / llama-swap → 閘道 → 向量庫 → MCP 伺服器 (容器) → 代理服務 → 介面 → Caddy → 可觀測性.

```
[使用者] --Tailscale--> [Caddy :443 (TLS, 基本驗證, 速率限制)]
                              |
                              v
                       [介面 (SSO 可選)]
                              |
                              v
        [代理服務 (LangGraph)] ---> [閘道 LiteLLM / Bifrost (內網, 管理路徑封鎖)]
             |        |                         |
             |        |                         v
             |        |                   [llama-swap -> 推論引擎]
             |        v
             |   [MCP 伺服器容器: 非 root, 唯讀, 限制對外連線, 只掛指定資料夾]
             v
      [程式碼沙箱: --network none, rootless / gVisor]
      [Langfuse (可選) <- OTel 追蹤]
```

**在前兩組的檢核表之上, 另加**:

- [ ] 閘道與 MCP 映像以摘要值鎖定, 並訂閱 GitHub Security Advisories
- [ ] 閘道管理端點只限管理者 IP
- [ ] 每位使用者或每個應用各一把虛擬金鑰, 並設用量上限
- [ ] 代理的寫入與刪除動作需要人工確認
- [ ] 沙箱無網路, 並有資源上限
- [ ] MCP 工具描述變更時重新審核
- [ ] 金鑰輪替程序已準備, 並演練過一次

## 9.4 硬體等級對應

| 等級 | 建議架構 | 備註 |
|---|---|---|
| A 無獨顯筆電 | 最小組合 (AnythingLLM 桌面版) | RAG 只用小型嵌入模型; 不跑代理 |
| B 8 至 12GB 顯示卡 | 最小組合, 或精簡標準組合 | 嵌入模型放 CPU, 保留顯示記憶體 |
| C Apple Silicon | 16GB 用最小組合; 32GB 以上可用標準組合 | 依統一記憶體決定 |
| D 16GB 顯示卡 | 標準組合 | llama-swap 輪替對話與嵌入模型 |
| E | 標準組合; 小團隊可加 LangGraph | 使用 Langfuse 須確認系統記憶體 32GB 以上 |
| F | 進階組合 | 有人能每週維運時才採用 |

資料來源: 研究 2 第 12.4 節, 屬推論, 信心: 中.
